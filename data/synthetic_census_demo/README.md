# Runnable Census-Mechanics Demo (fictional rule, privacy-safe)

Generated by `scripts/run_synthetic_census_demo.py` (seed 42, 20,000 rows).

## Why this is separate from `../synthetic_demo/`

`../synthetic_demo/` is a **code-paths-only** file: its label is independent of
every non-label-source field, so the determinism census correctly finds *no*
determinism there. That demonstrates the pipeline runs but does not let a reader
watch the census actually recover determining keys.

This demo fills that gap. It applies an **explicit, published, fictional policy
rule** so that determinism genuinely holds, and it runs the full census
mechanics on it. It reveals nothing about the real deployment (the rule is
invented and printed in full below); it only shows that the census logic is
correct and reproducible on data with the processed schema.

## The fictional rule (fully disclosed)

Four independent policy bits `b1..b4 ~ Bernoulli(0.25)`. The decision depends on
their sum only:

```
sum(b1..b4) == 4  -> Deny
sum(b1..b4) == 3  -> Drop
otherwise         -> Allow
```

Each bit is revealed exactly (via disjoint value vocabularies) by two schema
fields — the "policy groups":

| bit | encoding fields |
|-----|-----------------|
| b1  | Source Port, Destination Port |
| b2  | Source Zone, Destination Zone |
| b3  | Application, Category |
| b4  | IP Protocol, Inbound Interface |

The other 16 core fields are drawn independently of the label and kept
low-cardinality (so contexts stay dense and no sparsity-driven spurious
determinism appears). The three label-source fields are made consistent with the
label through the *published* target-construction grammar only.

## What the census recovers (see `synthetic_census_demo_report.json`)

- **No determining subset of size ≤ 3** (all 2,324 checked) — the decision needs
  all four policy groups.
- **Exactly 16 minimum four-field determining keys** — one field from each of the
  four groups (2×2×2×2), enumerated in `synthetic_census_demo_keys.csv`.
- **H(Y|V) = 0** on any view that carries all four groups; **H(Y|V) > 0** as soon
  as a group is withheld (e.g. 0.078 bits with the Application group removed,
  0.123 bits with only three groups).
- Every recovered key is independently re-verified by a pandas group-by (OK).

## What it deliberately does NOT claim

It does **not** reproduce, and is not a surrogate for, the enterprise export's
determinism, its seven `{Source Port, Bytes}` four-field keys, its proxy
structure, or its near-perfect scores. Those rest on the restricted data and, as
the manuscript's Data availability statement explains, any surrogate faithful
enough to reproduce them would re-encode the protected dependency structure. The
recovered "16 keys" here belong to the fictional rule alone. The value of this
demo is that a reader can execute the determinism/entropy/key-census code end to
end and confirm it behaves correctly, without any access to the real logs.

## Reproduce

```
python scripts/run_synthetic_census_demo.py
```
Runtime is typically under one minute on a current desktop. The command writes
a generated record-level synthetic CSV (ignored by Git) plus the aggregate
recovered-keys CSV and JSON report in this folder.
